# mustShip site

Одностраничный статический сайт mustShip: услуги, проекты, команда и контакты. Адаптивная вёрстка, иллюстрации, локальные шрифты, переключаемые проекты с просмотром экранов и копирование email. Сборка и внешние API не нужны.

Раздел «Что делаем» обновлён 23 октября 2026: пять услуг из согласованного макета, крупные тексты и самостоятельные карандашные рисунки по углам карточек. По согласованному макету рисунки мягко заходят под края текста; профиль ИИ-консультанта отражён лицом влево, окончание его описания набрано по одному слову на строку. Буквы остаются на переднем плане с мягким просветом цвета бумаги. Адаптив обновлён 24 октября 2026: карточки сохраняют ширину до 260 px и переносятся по одной по мере сужения окна (5 → 4 → 3 → 2 → 1). Неполные ряды центрируются; на узких экранах карточка помещается в доступную ширину. Описания остаются HTML-текстом. `assets/service-*-study.webp` — отдельные экспорты из согласованной сгенерированной концепции с удалённой бумажной подложкой; это условные иллюстрации услуг, не снимки продуктов. `assets/services-approved-title.webp` содержит только рукописные буквы, доступное название раздела сохранено в HTML. Подчёркивание повторяет восходящий мазок из макета через SVG-маску и однотонный CSS-цвет #107038, без растровых примесей. Новых библиотек и сетевых запросов не добавлено.

Сайт: [gushinets.github.io/mustship-site](https://gushinets.github.io/mustship-site/).

## Запуск

Из корня репозитория:

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

Открыть http://127.0.0.1:4173/.

## Проверка

Проверка файлов и основных ссылок без зависимостей:

```powershell
python tests/site-smoke.py
```

При сервере на порту 4194 и доступном Node-пакете Playwright: `node tests/hero-proof.cjs`. Проверяет шесть вариантов карточки на 19 размерах окна (114 сочетаний): вмещение в экран ноутбука, отсутствие обрезки, кнопки от 44 px, подпись вне экрана, ссылки, переход к выбранному проекту, фокус, увеличение и запасной вариант без JavaScript. На настольных размерах от 1100 px проверяет положение текстов слева от рисунка и видимость карточки/кнопок без прокрутки при высоте окна от 572 px; в более низких окнах допускается вертикальная прокрутка без обрезки содержимого. На узких экранах проверяет порядок «заголовок → рисунок процесса → ноутбук с проектом → текст → иконки» и соответствующий порядок фокуса. Перед замером ожидает загрузку актуального responsive-изображения. По умолчанию используется Microsoft Edge; другой канал можно задать через `PLAYWRIGHT_CHANNEL`. Playwright должен разрешаться обычным способом или через `NODE_PATH`.

При работающем сервере и установленном Playwright CLI:

```powershell
playwright-cli -s=mustship-reference open http://127.0.0.1:4173/
playwright-cli -s=mustship-reference run-code --filename=check.cjs
```

Проверяет диалоги, возврат фокуса, якоря, копирование email, контраст, области нажатия и адаптивность на ширинах 320–1440 px. Скриншоты сохраняются в `output/playwright/`.

## Публикация и материалы

GitHub Pages публикует корень ветки `main`. Все пути к ресурсам относительные, поэтому сайт работает по адресу репозитория.

После изменения CSS или JS обновите соответствующий `?v=` в `index.html` на первые 12 символов SHA256 файла. Для `styles.css` и `hero.css` используется UTF-8-текст с нормализованными окончаниями строк LF. Это обновляет кэш ресурсов на телефонах; `tests/site-smoke.py` проверяет версии.

Шрифты Neucha, Nunito и Pangolin находятся в `assets/` вместе с лицензиями. `assets/logo.jpg` — предоставленный пользователем логотип; исходная картинка сохранена без изменений. `assets/artwork.png` — сгенерированный по референсу макет: CSS использует его фотографии и фактуру уголка бумаги. Четыре карандашные иллюстрации процесса сгенерированы встроенным imagegen и сохранены в `assets/process-*-pencil.webp` с прозрачным фоном. Промпты — в `docs/imagegen/process-pencil-prompts.md`. Остальные надписи реализованы текстом, иконки и рисунки — в SVG, мини-интерфейсы проектов — в HTML/CSS.

Контакт: MustShip.gushinets@gmail.com. Платные сервисы, аналитика и внешние API не подключены. `docs/` содержит документы предыдущей версии дизайна.

Раздел «Наши проекты» обновлён 24 октября 2026: над экраном находятся шесть компактных вкладок с карандашными иконками. Подписи обозначают направления задач: «Работа с голосом», «Поиск и анализ данных», «Анализ по критериям», «Создание промптов», «Улучшение промптов», «Проверка решений в 3D». Внутри показаны конкретные проекты с полными описаниями. Закладки экранов и увеличение находятся над изображением; ссылки открытия продукта и обсуждения выровнены по одной линии на широком экране. Обсуждение ведёт к контактам сайта. Повторяющиеся рамки, промоблок, пометки типа проекта и нижние подписи убраны; происхождение кадров указано в увеличенном просмотре.

`projects.css` ограничен `#projects`, логика вкладок и увеличения находится в `projects.js`. В `assets/projects/` сохранены 14 реальных/демонстрационных кадров и кистевой заголовок. `assets/projects/icons/` — шесть сгенерированных карандашных иллюстраций в палитре сайта, WebP 192×192; это символы направлений, не скриншоты. Их суммарный размер около 146 КБ. Кадры продуктов сохранены без графических изменений; доступное название раздела остаётся HTML-текстом. Схема PromptEngineerBot — иллюстрация последовательности диалога. Резюме CV Screener вымышленные, ответы сохранённые; ScopeCreepGuard и PromptOptimizer показывают подготовленные демонстрационные данные. Хозблок — эскиз внутреннего проекта. Экраны ScopeCreepGuard взяты из [закреплённой версии проекта](https://github.com/gushinets/ScopeCreepGuard/tree/9f568200ce93cefcc0f0ce557219f56d4a404ede/docs/screenshots). Неподтверждённая карточка Chrome Web Store не подключена. Новых API, аналитики или формы отправки нет.

Первый экран перекомпонован 29 октября 2026: заголовок расположен слева от салфетки, существующие тексты, преимущества и общие кнопки — ниже, слева от ноутбука. Живая карточка случайного проекта помещена поверх светлой области его экрана с описанием и двумя рабочими ссылками. Область карточки выровнена по внутренним границам заново нарисованного дисплея; на планшетных ширинах рамка экрана видна полностью. Подпись «✓ реализовано» находится под ноутбуком ближе к правому краю на всех ширинах; обе стрелки указывают вверх на ноутбук. Новый `hero.css` ограничен первым экраном; логика выбора в `projects.js` сохранена. На узких экранах порядок блоков: заголовок, рисунок процесса, ноутбук с проектом, текст, иконки, общие кнопки. Он совпадает с порядком HTML и фокуса; миниатюра скрывается при недостатке ширины. Горизонтальная прокрутка для чтения не требуется. Переход к услугам остаётся без разделителя; пояснение выровнено вправо.

`assets/hero-approved-title.jpg`, `hero-approved-art.jpg` и `hero-approved-realized.jpg` — чистые экспорты согласованных SVG-компонентов в браузере из сгенерированной концепции, без поля рецензирования и маркеров. Новая генерация при переносе не использовалась. Рисунок разработки условный; `assets/hero-live-translator-sketch.webp` — сгенерированная карандашная иллюстрация по реальному интерфейсу Live Translator в палитре первого экрана. Это иллюстрация, а не скриншот. Экспорт этой миниатюры в WebP сохраняет исходные RGBA-пиксели без изменений. `assets/live-translator.png` — исходный экран реального проекта. Кнопки обсуждения ведут к контактам, ссылки проектов — к разделу портфолио. Панель согласования и её заглушки в сайт не включены.

Карточка первого экрана обновлена 28 октября 2026: при открытии страницы случайно выбирается один из шести проектов, затем карточка остаётся на месте без автоматической смены. Её заголовок берётся непосредственно из подписи соответствующей вкладки «Наши проекты», описание обозначает направление задач. Публичное демо переводчика, бота или 3D-модели открывается в отдельной вкладке; у CV Screener, ScopeCreepGuard и PromptOptimizer кнопка «Посмотреть пример» выбирает нужный проект в портфолио. Без JavaScript доступна карточка «Работа с голосом» со ссылкой на переводчик.

`assets/projects/hero/{cv,scope,model,prompt,bot,translator}-window.webp` — шесть вертикальных карандашных иллюстраций, созданных встроенным imagegen. По уточнению 28 октября показаны только упрощённые окна сервисов без ноутбуков, мониторов и телефонов: несколько крупных элементов передают основную задачу и результат. Пять сценариев основаны на опубликованных экранах продуктов, бот — на существующей схеме диалога. Это условные иллюстрации сценариев, а не точные скриншоты или утверждение о существовании отдельной мобильной версии; исходные кадры портфолио не изменены. Ширина WebP — 359–360 px, высота — 638–756 px, прозрачность сохранена. Общий объём шести миниатюр — 436440 байт (около 436 КБ). Происхождение указано в alt; ограничения примеров остаются в увеличенном просмотре исходных кадров. Аналитика, cookies, хранение истории посетителя и подбор по источнику перехода не подключены.
